# 0014. Вся видимая копия страниц — в `data/`, двенадцать модулей (отмена ADR 0011, дополнение ADR 0001)

## Контекст

ADR 0001 зафиксировал слой данных из ровно шести модулей (`business`, `services`, `towns`,
`reviews`, `brands`, `b2b-segments`). ADR 0011 оставил разовую редакционную копию, у которой
один потребитель, прямо в компонентах: прозу `/about`, `TOWN_SEO` и `CHARLOTTE_REPAIR_CHIPS`
в `app/towns/[slug]`, `SECTION_H2` в `app/appliance-repair/[slug]`, тексты секций главной и
хаба `/for-business`.

Бриф прогона `entity-commercial-geo` (2026-09-28) говорит прямо: «Тексты и константы живут
в data/, компоненты контент не хардкодят». К тому же у прогона появились блоки, которые
ждут факта от владельца и должны иметь статус `draft`/`published` (ADR 0015), имя владельца
обязано браться из одного места во всех текстах, alt, JSON-LD и `<title>` (R11), а
проверки шаблонности и запретных слов читают тексты страниц.

## Решение

Вся видимая копия всех роутов переехала в `data/`, не только страниц, которые менял прогон.
Страницы и компоненты получают тексты из данных и не держат JSX-литералов с
пользовательским текстом. Исключение — поведенческие строки формы: плейсхолдеры полей и
сообщения валидации остаются рядом с `components/BookForm.tsx` и `lib/book/schema.ts`,
потому что это поведение формы, а не контент страницы.

К шести модулям ADR 0001 добавились шесть новых (плюс `data/types.ts` — только типы):

| Модуль | Что держит |
|---|---|
| `data/site.ts` | тексты шапки и подвала, ярлыки меню (`site.nav`), общие ярлыки ссылок, текст плашки DRAFT |
| `data/people.ts` | `owner` (имя «Constantin», роль, опыт, сертификаты, фото с alt) + вся копия `/about` (`aboutPage`, блоки со статусом) |
| `data/home.ts` | копия главной и её SEO-строки; `whoWeServeCards()`, `homeWhereWeWork()` |
| `data/commercial.ts` | копия хаба `/commercial-appliance-repair` (бывш. `/for-business`) + 7 дочерних страниц |
| `data/guides.ts` | категории и статьи центра знаний + копия шаблона (ADR 0019) |
| `data/cases.ts` | кейсы ремонта (сейчас пусто) + копия шаблона |

Прежние модули расширены по месту: `TOWN_SEO` → `TownPage.seo`, `CHARLOTTE_REPAIR_CHIPS` →
`TownPage.repairChips` (`data/towns.ts`, там же `townPageCopy`, `areaCopy`, `townsIndex`);
`SECTION_H2` → `Service.sectionHeads`, общая копия страниц услуг → `servicePage`, бытовой хаб →
`applianceRepairHub` (`data/services.ts`); копия `/reviews` → `reviewsPageCopy`
(`data/reviews.ts`). Меню по-прежнему не модуль, а производная (`lib/nav`, см. ADR 0001, 0021).

Имя бизнеса в текстах и `<title>` — только `business.name`, имя владельца — только
`owner.name`; другие написания в `data/` не заводятся.

## Почему

- **Оставить ADR 0011 в силе** — отвергнуто: бриф прямо требует обратного. Кроме того, блок,
  который ждёт факта, должен нести `status` (ADR 0015); JSX-литерал нельзя сделать черновиком,
  а объект в `data/` — можно одной правкой поля.
- **Перенести только копию страниц, которые меняет прогон** — отвергнуто: получились бы два
  правила сразу («эта копия в данных, та в компоненте»), а граница «разовый абзац или нет»
  и так была слабым местом ADR 0011 (его «Последствия»: «вопрос суждения»).
- **Один общий файл текстов (`data/copy.ts` / `data/pages.ts`)** — отвергнуто: копия лежит
  рядом с данными своей сущности — страница района в записи района, H1 услуги в записи
  услуги, статья в статье. Статус, факты и тексты сущности остаются в одном объекте; общий
  файл текстов разрезал бы сущность на два места.
- **Держаться шести модулей ADR 0001** и раскладывать новое по старым — отвергнуто: владелец,
  коммерческие страницы, статьи и кейсы — самостоятельные сущности со своими типами; втиснутые
  в `b2b-segments` или `services`, они сделали бы эти модули свалкой.

## Последствия

- ADR 0011 отменён. ADR 0001 дополнен: модулей не шесть, а двенадцать; принцип «`data/` —
  единственный источник, потребители только читают» не изменился.
- Появилось одно место, где можно вычитать все тексты сайта разом, — закрыт пункт
  «Последствий» ADR 0011 «нет единого места».
- Копирайтеру для правки текста по-прежнему нужен TypeScript-файл и пересборка (как в ADR 0001).
- Правило «нет JSX-литералов с текстом» проверяется ревью (grep по `app/**` и
  `components/**`), а не тестом. Видимый текст опубликованных страниц дополнительно проверяет
  `npm run check:copy` по собранному HTML (запретные слова, кириллица).
