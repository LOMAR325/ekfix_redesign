# 0003. Без `output: 'export'` — все страницы SSG плюс один серверный роут

## Контекст

Бриф требует одновременно «SSG для всех страниц» и «реальный Route Handler
`app/api/book/route.ts`»; `next/image`-оптимизация из `public/images/` тоже в
требованиях.

## Решение

`next.config.ts` без `output: 'export'`. Все страницы остаются статическими
(статический рендер + `generateStaticParams`, без `dynamic`/`revalidate`);
единственный серверный элемент — `POST /api/book`.

## Почему

- **`output: 'export'`** (полностью статический билд под текущий статический
  хостинг) — отвергнуто: он физически исключает Route Handler'ы и рантайм-оптимизацию
  картинок. Пришлось бы либо пожертвовать «реальным `/api/book`» (приоритет №1
  брифа), либо унести форму на сторонний сервис.
- **Полный SSR / `revalidate`** — отвергнуто: контент правится пересборкой, не в
  рантайме; динамический рендер только раздул бы TTFB и требования к хостингу без
  единой выгоды.
- **Вынести форму на внешний обработчик** (Formspree и т.п.), оставив `export` —
  отвергнуто: бриф хочет владение логикой приёма заявки в репозитории плюс
  заглушки-адаптеры под будущую доставку (см. 0010).

## Последствия

- Сайту теперь нужен Node-хостинг, не статический. Текущий staging на
  `zholudz.com/...` — статический; для продакшена нужна другая площадка — **пункт
  отчёта владельцу**.
- Появляется серверный рантайм, который надо мониторить и патчить (поверхность атаки,
  обновления Node).
- Выигрыш: одна кодовая база и для страниц, и для приёма заявки; `next/image`
  работает штатно.
