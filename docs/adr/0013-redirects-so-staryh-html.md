# 0013. Редиректы со старых `.html`-URL (отмена ADR 0012)

## Контекст

ADR 0012 (2026-09-01) отказался от `redirects()` со старых `*.html`: «нет доказанной
нужды, бриф просит ничего не додумывать; старые URL не проиндексированы на проде,
внешних ссылок нет». 2026-09-02, готовя сайт к боевому запуску, владелец решил
подстраховаться: перед переездом с прежнего сайта важнее не потерять случайный
трафик, чем держать конфиг минимальным.

## Решение

В `next.config.ts` добавлена `async redirects()` — 7 правил, все `permanent: true`
(HTTP 308), со старых `*.html` на чистые роуты:

- `/index.html` → `/`
- `/about.html` → `/about`
- `/brands.html` → `/brands`
- `/for-business.html` → `/for-business`
- `/appliance-repair/:slug.html` → `/appliance-repair/:slug`
- `/towns/index.html` → `/towns` (правило стоит ДО параметрического ниже)
- `/towns/:slug.html` → `/towns/:slug`

## Почему

- Что изменилось с ADR 0012 — прямое решение владельца подстраховаться перед боевым
  запуском. Появилось основание, которого в 0012 не было.
- Риск, который закрываем: если по старому `.html` кто-то придёт (каталог, чужая
  закладка, поисковый индекс, не успевший обновиться после переезда) — он получит
  404, и трафик по этим адресам просядет. Аудит (`ek-global-site-issues.md` §2.9)
  вынес это как P2-риск.
- **Оставить как в ADR 0012** — отвергнуто: теперь есть основание (решение владельца),
  а правка тривиальна.
- **Сначала полный аудит бэклинков (Search Console)** — отвергнуто: это офлайн-задача,
  она не блокирует страховочную правку конфига; редиректы не вредят, даже если
  входящих ссылок окажется ноль.

## Последствия

- 7 правил в `next.config.ts`; проверяются тривиально — `curl -I` должен вернуть
  `308` и `location` на чистый роут.
- Редирект-циклов нет: все цели — существующие роуты (`/`, `/about`, `/brands`,
  `/for-business`, `/appliance-repair/:slug`, `/towns`, `/towns/:slug`), сами по
  `.html` не заканчиваются.
- Если позже появятся новые `.html`-подобные пути — список правил расширяется
  точечно.
