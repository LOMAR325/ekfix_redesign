# 0002. `app/globals.css` — дословная копия старого CSS, без Tailwind/CSS-in-JS

## Контекст

`css/style.css` — единственный носитель визуала текущего сайта; этап явно объявлен
«не редизайн, результат попиксельно идентичен».

## Решение

`css/style.css` переносится в `app/globals.css` дословно, импортируется один раз в
`app/layout.tsx`. Единственное добавление — блок `.card-grid-4` (копия `.card-grid-3`
на 4 колонки с тем же адаптивом). Новый `<select>` в форме CSS не требует — его ловит
существующее правило `.book-form select`.

## Почему

- **Переписать в Tailwind** — отвергнуто: это дефолт миграций на Next и его прямо
  предлагает `create-next-app`, но перевод сотен правил на утилитарные классы
  гарантированно даёт пиксельный дрейф (иные значения отступов и типографики при
  округлении к шкале), а бриф требует буквального 1:1 и поимённо запрещает Tailwind.
- **CSS-in-JS / CSS-модули** — отвергнуто: та же цена ручного переноса каждого
  правила плюс риск смены специфичности и порядка каскада; ноль выгоды на статическом
  сайте без динамических тем и без переиспользуемых на других проектах компонентов.
- **Причесать CSS «заодно»** (мёртвые правила, переменные) — отвергнуто: любой diff
  в этом файле неотличим от регрессии на попиксельной сверке; чистка отложена до
  после переноса.

## Последствия

- `globals.css` заморожен: правки только по явному согласованию, каждая — риск для
  всего сайта разом.
- Наследуется весь технический долг старого CSS: глобальная специфичность, мёртвые
  правила, отсутствие модульности.
- Нет tree-shaking CSS — весь файл грузится на всех страницах (приемлемо: он невелик
  и кэшируется).
- `.card-grid-4` — единственное место, где «1:1» формально нарушено; зафиксировано
  в критериях приёмки.

> **Уточнено 2026-09-02 (заход audit-fixes):** для фикса контраста заголовков `.audience-card` (issues §2.1) добавлена ещё одна точечная строка — `.audience-card h3 { color: var(--text-light); }`. Файл теперь = старый CSS + `.card-grid-4` + эта строка. Бриф захода это санкционировал.

> **Пересмотрено 2026-09-03 (заход `ux-polish`, коммит `6f2ae17`):** принцип «`globals.css` —

> 2. Удалён блок `.side-rail*` (вместе с `components/home/SideRail.tsx` и `<SideRail/>` в `app/page.tsx`).
> 3. У 6 акцентных текстовых ссылок снято подчёркивание — `.not-listed a`, `.brand-note a` и
>    инлайн `border-bottom` в Hero / audience-card / BrandsSection / appliance-repair. Сигнал —
>    цвет + стрелка `→`; добавлены hover (осветление) и `:focus-visible` (outline). Инлайн-ссылки
>    покрыты селектором `a[style*="--accent"]`, без нового класса.
> 4. `.call-pill` `font-size` 14→15px; на ≤480px номер телефона больше не прячется.
> 5. Удалена `.call-dot` — `span` в `Header.tsx`, правило и `gap` в `.call-pill`.
> 6. Мост `.nav-dropdown::before` — дропдауны хедера раскрываются по hover на десктопе (≥861px).
>
> **Осталось в силе:** никаких Tailwind / CSS-модулей / CSS-in-JS / новых классов вне тех, что
> были в старом HTML; правка CSS допустима только точечная и только с записью в этот ADR; визуальная
> идентичность остальному сайту сохраняется. Спонтанная чистка мёртвых правил / рефактор — по-прежнему нет.
>
> **Последствие:** `globals.css` теперь живёт и правится; «эталон визуала в git-истории» остаётся
> ориентиром, но не догмой.

> **Продолжение 2026-09-03 (заход `ux-polish-2`):** ещё две правки CSS по фидбегу владельца,
> под тем же санкционированным режимом «точечно + запись в ADR».
>
> **Контекст:** секции сайта разделялись волосяной линией `border-top: 1px solid rgba(255,255,255,.1)`
> у `.section-dark` / `.section-dark-2` / `.cta-band`; светлые секции — ничем (сливались). Плюс
> два блока фактов (`.family-stats` на главной, `.stat-row` на `/about`) были нарисованы «квадратом»
> — жёсткая 1px-сетка с острыми углами — на фоне скруглённых карточек всего остального сайта.
>
> **Решение:**
> 1. Все `border-top`-линии-разделители сняты. Разделение секций держится на **шаге фона +
>    крупных отступах** (`.section` padding `clamp(72px,9vw,120px)`). Добавлен класс
>    `.section-light-2` (`--bg-light-2` `#e7e9e2`). Тёмные оттенки разведены сильнее:
>    `--bg-dark-2` `#101110`→`#141613`, `--bg-dark-3` `#131513`→`#1b1d18` (карточки на тёмном),
>    `--bg-dark-4` `#161815`→`#212320` (`.book-card`). Инвариант: **две соседние секции никогда
>    не одного оттенка** — компоненты страниц чередуют light / light-2 / dark / dark-2
>    (переназначены: `#who-we-serve`, `#trust-b2b`, `#book`, for-business `segments` и `#process`).
> 2. `.family-stats` — из 2×2 «1px-сетки» в 4 отдельные скруглённые мини-карточки `.fstat`
>    (`--bg-dark-3`, `border-radius:18px`) с лаймовой иконкой в чипе `.fstat-ic` (инлайн-SVG
>    в `FamilySection.tsx`, `aria-hidden`). `.stat-row` (about) — тем же образом в скруглённые чипы.
>
> **Почему так, а не иначе:** рассматривали (а) скруглённые панели внахлёст «колодой карт» —
> отклонено как слишком большой сдвиг вёрстки и ощущения прокрутки на всех страницах;
> (б) мягкий градиент-свечение на стыке — отклонено, всё ещё «линия», просто размытая.
> Владелец выбрал «убрать линии, ступень тона».
>
> **Последствие:** порядок оттенков секций теперь несёт смысловую нагрузку — при добавлении/
> перестановке секции нужно проверять соседей (зафиксировано в `CLAUDE.md`). Появился второй
> санкционированный новый класс — `.section-light-2` (после `.card-grid-4`).
