# 0020. Боевой домен `ekfix.us` подтверждён; таблица редиректов старого сайта в `lib/redirects` (отмена ADR 0005, дополнение ADR 0013)

## Контекст

ADR 0005 держал `data/business.siteUrl = "https://ekfix.us"` как помеченную заглушку
(`// TODO: подтвердить финальный публичный домен`): домен не был подтверждён, отдавать сайт в
индекс до ответа владельца было нельзя. ADR 0013 добавил в `next.config.ts` 7 правил 308 со
старых `*.html` статического сайта.

Бриф прогона `entity-commercial-geo` (2026-09-28): волна 1 называется «Единая сущность и
переезд на боевой домен»; 1.4 — «На ekfix.us сейчас работает старая версия сайта со своими URL
(включая десятки однотипных страниц городов); новый сайт её заменит. Получи список старых
адресов … и добавь постоянный редирект каждого на ближайший по смыслу новый роут: город без
своей страницы → /towns, услуга → соответствующая услуга и т.д. Не сваливай всё на главную»;
проверка перед сдачей — «Все старые URL (zholudz *.html, /for-business, адреса старого
ekfix.us) отдают постоянный редирект на живую страницу». Список получен 2026-09-28 из
`https://ekfix.us/sitemap.xml` (43 адреса; прямой `curl` упирается в Cloudflare 403) и лежит в
`.autopilot/2026-09-28-entity-commercial-geo--wip/old-ekfix-urls.txt`.

## Решение

- **Домен.** `business.siteUrl = "https://ekfix.us"` без `TODO`. Canonical, `metadataBase`,
  sitemap и все `@id` JSON-LD по-прежнему строятся только от него (`lib/seo.absoluteUrl`).
- **Таблица редиректов — чистая функция.** `lib/redirects.ts` → `redirectRules()`;
  `next.config.ts` лишь возвращает её из `async redirects()`. Все правила `permanent: true` (308):
  - 7 правил `.html` из ADR 0013; `/for-business.html` теперь ведёт сразу на
    `/commercial-appliance-repair` (ADR 0016), без цепочки через `/for-business`;
  - `/for-business` → `/commercial-appliance-repair`;
  - 43 пути старого ekfix.us дословно (`OLD_EKFIX_PATHS`).
- **Назначение вычисляется, а не пишется руками.** «Живой» — значит входит в
  `lib/routes.publishedPaths()`. Для старого пути по порядку: совпадает с живым — правила нет
  (`/`, 10 услуг, `charlotte`, `matthews`, `/brands` — 14 адресов); после замены `_` → `-` и
  нижнего регистра совпал с живым — туда (`garbage_disposal`, `ice_maker`, `rock_hill`,
  `fort_mill`, `indian_trail`); иначе — индекс раздела (21 город без страницы → `/towns`);
  старые коммерческие лендинги (`OLD_COMMERCIAL`: `property_management`,
  `property_management_cafe`, `laundry_equipment_repair`) — на опубликованную дочернюю страницу,
  а пока она черновик — на якорь хаба (`#property-management`, `#horeca`, `#laundry`). Путь, для
  которого ничего не нашлось, роняет сборку с ошибкой, называющей этот путь.
- **Регистр и слеш (поправка D02).** Сопоставление `source` в `redirects()` у Next по умолчанию
  регистронезависимое (`caseSensitiveRoutes` выключен): правило `/towns/Lesslie` ловит и
  `/towns/lesslie`. Поэтому код бросает ошибку, если назначение отличается от источника только
  регистром (иначе — петля). Путь со слешем в конце проходит два 308 — нормализация Next, затем
  наше правило — и заканчивается на живой странице.
- **Шов 4** (`lib/redirects.test.ts`): все 43 старых URL покрыты или совпадают с живым путём;
  каждое назначение ∈ `publishedPaths()` (якорь отбрасывается); нет цепочек (назначение не
  является источником другого правила); не-корневые не ведут на `/`.

## Почему

- **Оставить заглушку ADR 0005** — отвергнуто: бриф прямо называет `ekfix.us` боевым доменом,
  который новый сайт заменяет. Риск, ради которого была пометка (canonical на неверный домен),
  снят.
- **Свалить старые адреса на главную** — отвергнуто брифом («Не сваливай всё на главную»):
  массовый редирект на нерелевантную страницу поисковики воспринимают как мягкий 404, а
  посетитель не находит то, за чем пришёл.
- **Статическая таблица из 43 пар «источник → назначение» в `next.config.ts`** — отвергнуто:
  назначения разъехались бы со статусами (коммерческая страница опубликована или черновик,
  страница города снята) и могли бы вести на 404. Вычисление от `publishedPaths()` держит
  инвариант «только на живую страницу», и тест его проверяет.
- **Отдельное правило под каждый вариант регистра** (исходное предположение спецификации §5) —
  отвергнуто после D02: Next и так сопоставляет без учёта регистра, дубль был бы мёртвым правилом.
- **404 для старых адресов 21 города без страницы** (как ADR 0008 поступает с любым неизвестным
  slug) — отвергнуто для этих 21 адреса: они жили на боевом домене и могли быть в индексе и в
  закладках, а `/towns` называет эти города в списках «также обслуживаем». Любой другой
  неизвестный `/towns/<slug>` по-прежнему 404.

## Последствия

- ADR 0005 отменён. ADR 0013 дополнен: его 7 правил живут теперь в `lib/redirects.ts`, а не
  литералом в `next.config.ts`; назначение `/for-business.html` изменилось.
- Редиректы зависят от данных: снять коммерческую дочернюю страницу с публикации — старый
  лендинг сам переедет на якорь хаба при следующей сборке.
- Адреса старого сайта вне его sitemap (если они есть) владелец выгружает из Search Console
  («Страницы» / «Ссылки») и дописывает путь в `OLD_EKFIX_PATHS`; назначение посчитается само,
  а для пути без очевидного соответствия — запись в `OLD_COMMERCIAL` (иначе сборка упадёт с его
  именем).
- Сам выкат на `ekfix.us` (Node-хостинг — ADR 0003, DNS, Search Console, GBP) — шаг владельца
  вне кода. До выката canonical нового сайта указывает на домен, где пока работает старый сайт.
