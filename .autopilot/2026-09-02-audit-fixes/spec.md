# Спецификация: EK Global — закрытие дефектов после аудита 2026-09-02

## Задача

Сайт перенесён на Next.js и работает, но аудит нашёл конкретные дефекты. Посетитель
на главной не видит названий четырёх карточек «Who we serve» (контраст 1.07:1). На
`/for-business` в текст попал русский служебный маркер `[TODO: …]`. Форма заявки
принимает лид, но никуда его не отправляет — исходная причина «с сайта нет лидов»
не закрыта. Плюс мелочи: карточки коммерческой техники показывают не ту технику,
пункт меню не подсвечивается на вложенных страницах, старые `.html`-адреса отдают 404.

## Решение

Все семь дефектов закрыты точечными правками, без изменения дизайна и без новых
зависимостей. Заголовки карточек читаются. Русского текста и служебных маркеров на
сайте нет. Форма реально доставляет лид на почту (Resend) и/или в вебхук — включается
заполнением `.env`, код при этом не трогается; падение канала не роняет ответ формы.
Фото карточек техники — ближайшие по смыслу из имеющихся, с пометкой «временно».
Пункт меню снова подсвечивается. Старые `.html` отдают постоянный редирект.

## Решения по реализации

- **Задача 1 — фикс в `globals.css`, одна строка.** `.audience-card h3 { color: var(--text-light); }`
  — рядом с уже существующими `.audience-card .eyebrow/p/li` правилами, у всех них
  цвет задан там же. *Почему не инлайн-стиль в компоненте:* каждый другой текстовый
  элемент `.audience-card` красится в `globals.css`; строка завершает существующий
  блок, а не вводит новый визуальный язык. *Почему не переносить секцию на тёмный
  фон:* `#who-we-serve` = `.section-light` задано b2b-брифом и spec прошлого прогона
  (История 23), плюс тёмные карточки на светлом фоне — согласованный контраст
  (ADR прошлого прогона, `.card-grid-4` «тот же фон карточки»). **Отклонение от
  ADR 0002** («globals.css = копия + ровно `.card-grid-4`») — осознанное, бриф этого
  захода разрешает точечный CSS; в отчёт + приписка к ADR 0002.
- **Задача 2 — фильтр `placeholder` на слое данных.** `data/b2b-segments.ts`:
  `export const publicForBusinessSegments = forBusinessSegments.filter((s) => !s.placeholder)`.
  `app/for-business/page.tsx` строит `segmentCards` из `publicForBusinessSegments`,
  константа `HOA_NOTE` и ветка `segment.placeholder ? …` удаляются. Фильтр работает
  всегда (dev + prod) — строже, чем «в проде», и без dev/prod-расхождения рендера.
  Запись `hoa` в данных остаётся с `placeholder: true` и комментарием.
- **Задача 2 — скан кириллицы/маркеров.** Разовый скрипт (в тесте или как shell в
  тикете): поднять `next build && next start`, `curl` каждую из 22 страниц, вырезать
  текстовые узлы, грепнуть `[А-Яа-яЁё]` и `/TODO|FIXME|заглушк/i`. Ожидание: пусто.
  Не постоянный тест — разовая проверка приёмки.
- **ADR 0010 (форма-прототип) — не отменяется, дополняется.** Ядро ADR 0010
  (доставка за интерфейсом `LeadSink`, включается через `.env`, роут/форму не трогать)
  остаётся; задача 3 = ровно тот шаг, который «Последствия» ADR 0010 и предвидели
  («зарегистрировать sink»). Меняется одна деталь: `EmailLeadSink` больше не no-op.
  → приписка к `docs/adr/0010` («EmailLeadSink реализован в прогоне 2026-09-02»),
  нового ADR не нужно. В отчёт. Проверить `docs/adr/` на другие затронутые решения
  (напр. про рендер placeholder-сегментов — если такой ADR есть, дополнить).
- **Задача 3 — `EmailLeadSink` через `fetch`, без пакета `resend`.**
  `POST https://api.resend.com/emails`, заголовки `Authorization: Bearer ${RESEND_API_KEY}`
  + `content-type: application/json`, тело `{ from, to: BOOK_NOTIFY_EMAIL, subject, text }`.
  `from` — `"EK Global <onboarding@resend.dev>"` с комментарием «TODO: владелец —
  подтверждённый домен-отправитель в Resend» (пока не подтверждён домен, `onboarding@resend.dev`
  работает для тестовой отправки на собственный адрес). `send()` в `try/catch` →
  `console.warn` при сбое, не бросает. *Почему не пакет `resend`:* лишняя зависимость
  ради одного `POST`; `WebhookLeadSink` уже так устроен — единый стиль.
- **Задача 3 — единый обработчик ошибок sink.** Вынести `try/catch + console.warn`
  в базовый хелпер или в каждый `send()` одинаково; `submitLead` не меняется
  (`Promise.allSettled` уже изолирует). Тесты — мок `fetch` (`vi.fn`), мок env
  (`vi.stubEnv`), проверка «оба вызваны / один бросил → `{ok:true}` / ни одного
  канала → 0 вызовов».
- **Задача 4/5 — только `data/services.ts`.** Правка полей `image`, каждая с
  однострочным комментарием. `public/images` не трогать, картинки не добавлять.
- **Задача 6 — `basePath` в `lib/nav.ts`.** `NavGroup` +`basePath`; в `mainNav`
  «We Repair» → `/appliance-repair`, «Service Area» → `/towns`. `Header.tsx`:
  `const groupActive = (g) => pathname === g.basePath || pathname.startsWith(g.basePath + "/")`,
  класс `active` на `.nav-trigger`. Существующая подсветка дочерних `<Link>` не
  трогается.
- **Задача 7 — `redirects()` в `next.config.ts`.** Асинхронная функция, массив из 7
  правил, `permanent: true`. `:slug*` / `:path*` для параметрических. Проверка —
  `curl -I` возвращает `308` и `location` на чистый роут.
- **Тесты:** только vitest, только шов доставки (`lib/book`). Скан кириллицы, обход
  страниц, `curl -I` редиректов — разовые проверки приёмки, не постоянные тесты.

**Швы для тестов (Phase 5 тестирует ТОЛЬКО здесь):**

1. **`lib/book`** — `submitLead(input)`: валидный → `{ok:true}` + каждый `enabled` sink
   получил лид; невалидный → `{ok:false, errors}`, ни один sink не вызван; sink бросил
   → всё равно `{ok:true}`, остальные вызваны; ни одного `enabled` канала → `{ok:true}`,
   0 сетевых вызовов; `EmailLeadSink.enabled` / `WebhookLeadSink.enabled` следуют за env.
   Это единственный новый/тронутый шов. Существующие тесты `app/sitemap.test.ts`,
   `lib/jsonld.test.ts`, `app/api/book/route.test.ts` — не трогаются, остаются зелёными.
